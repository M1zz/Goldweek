# Goldweek 유료화 설계 (2.4.0~)

## 원칙

**쉬는 습관은 무료, 계획과 자동화는 Pro.**

무료만으로도 "연차를 놓치지 않고, 제때 쉬는" 생활이 되어야 한다. 그래야 사람이 남고, 남은 사람이 산다.
Pro는 "없어도 되지만 있으면 시간과 머리를 아껴 주는 것"에 둔다. 써 본 사람이 기꺼이 돈을 내는 지점이다.

나누는 질문 하나: **이 기능이 없으면 휴가를 놓치거나 기록이 틀리는가?**
그렇다면 무료다. 그렇지 않고 더 잘 쉬게 해 주거나 손을 덜어 주는 기능이면 Pro다.

## 무료: 건강하게 쉬는 데 필요한 것

| 기능 | 무료인 이유 |
|---|---|
| 연차·반차·반반차·시간 단위 기록, 남은 연차 | 앱의 바닥. 이게 막히면 앱이 아니다 |
| 근무 형태 (고정·파트타임·교대), 요일별 근무 시간 | 계산이 틀리면 신뢰가 무너진다 |
| 42개 나라 공휴일, 내 공휴일·방학, 휴가 불가 기간 | 정확성 |
| 올해 추천 전부 보기 + 3개 등록 | 앱의 "아하" 순간. 맛은 충분히 보여 준다 |
| 쉬는 간격·번아웃 안내, 알림, 위젯 | 건강하게 쉬도록 돕는 핵심 |
| 직접 만든 휴가 종류 (이름·색·순서), 종류별 합계 | 기록의 정확성 |
| 휴가 내역 사진으로 가져오기 | 처음 시작할 때 진입 장벽을 낮춘다 |
| iCloud 백업·복원, 타임머신 | 데이터 안전은 돈으로 막지 않는다 |
| 가족 일정 공유 | 공유받은 사람이 새 사용자가 된다 |

## 칸: 무료 · 플러스 · 프로 (2.4.2~)

자동차 트림처럼 위로 갈수록 앞 칸을 모두 포함한다. **주력은 프로**다.
2.4.2 에서 패밀리를 프로에 합쳤다. 함께 쉬기 · 가족 기념일은 이제 프로 기능이다.

| 칸 | 누구 | 더해지는 기능 | 언제부터 |
|---|---|---|---|
| **무료** | 모두 | 위 "무료" 표 전부 (가족 일정 보기 공유 포함) | |
| **플러스** | "알아서 짜 줘" | 최적 연간 플래너 | 원래 Pro |
| | | 추천 무제한 등록, 지난해·다음 해 추천 | 원래 Pro |
| | | 캘린더 앱으로 보내기 | 원래 Pro |
| **프로** | 규칙이 복잡한 사람 (교사·교대·보상휴가), 가족과 같이 계획하는 집 | 보너스 연차 | 원래 Pro |
| | | 종류별 연간 한도·넘겨 쓰기 | 2.4.0 |
| | | 학교 달력 가져오기 (사진·PDF·붙여 넣은 글) | 2.4.0 |
| | | 캘린더 자동 감지·가져오기 | 원래 Pro |
| | | 함께 쉬기: 가족 모두 쉬는 날(3일 이상)·한 사람만 연차 1~2일 내면 되는 날 (가족 탭 맨 위) | 2.4.0 패밀리, 2.4.2 프로 |
| | | 가족 기념일을 가족이 같이 보고, 그날 누가 일하는지·내 휴가 내기 | 2.4.0 패밀리, 2.4.2 프로 |

함께 쉬기는 공유받은 일정으로 센다: 각자 나라의 기본 주말·공휴일 + 공유한 종일 휴가 (반차·시간 단위는 쉬는 날 아님).
기념일은 CloudKit 새 기록 종류 `SharedAnniversary` 로 공유한다. 운영 환경에 스키마를 배포해야 하고,
배포 전에도 휴가 공유는 따로 저장하므로 깨지지 않는다.

가족 일정 **보기 공유**는 계속 무료다 (공유받은 사람이 새 사용자가 된다). 프로는 "보기"가 아니라 "같이 계획하기"를 판다.

2.4.0 전 페이월에 "iCloud 백업 = Pro"라고 적혀 있었지만 실제로는 무료였다. 백업은 무료로 두기로 하고 비교표에서 뺐다.

## 가격 (2.4.2~, 이 표가 원본)

유료 칸마다 **연 구독과 평생**을 나란히 판다. 구독만 있는 칸은 없다. 코드에는 가격을 적지 않는다(App Store 가 정한다).
`Goldweek/Goldweek.storekit` 의 값은 이 표의 미국 가격을 따른다.

| 상품 | ID | 미국 | 한국 | 판매 |
|---|---|---|---|---|
| 플러스 연 구독 | `com.Ysoup.LeaveWise.plus.annual` (plus.yearly 는 이미 쓰인 ID) | 9.99 USD | 17,000원 | 그대로 |
| **프로 연 구독** (기본 선택) | `com.Ysoup.LeaveWise.pro.yearly` | 19.99 USD | 33,000원 | 그대로 |
| 플러스 평생 | `com.Ysoup.LeaveWise.plus` | 29.99 USD | 52,000원 | 새로 |
| 프로 평생 | `com.Ysoup.LeaveWise.pro` (기존, ID 그대로) | 59.99 USD | 99,000원 | 올림 (49.99 에서) |
| 프로로 올리기 (플러스 평생 → 프로 평생) | `com.Ysoup.LeaveWise.pro.upgrade` | 29.99 USD | 47,000원 | 새로 |
| 구독 졸업 (구독자만 사는 프로 평생) | `com.Ysoup.LeaveWise.pro.graduate` | 41.99 USD | 69,000원 | 새로 |
| 패밀리 연 구독 | `com.Ysoup.LeaveWise.family.yearly` | | | **판매 중지** (2.4.2) |
| 선물 · 팁 | `.gift.pro` · `.tip.small/medium/large` | | | 그대로 |

- **처음 보는 사람에게 연 구독 첫 해 반값.** App Store 의 첫 구독 할인(introductory offer, 선결제 1년, 가격 절반)이고
  상품은 같은 연 구독이다. 화면 문구는 LeeoKit `LeeoTermPicker` 가 알아서 보인다. App Store Connect 에서 두 연 구독에 단다.
- 평생은 연 구독의 3배 언저리다. 평생 가격은 2026-11-17 에 올린다. 그날 전까지 페이월에 `LeeoLifetimePriceNotice` 한 줄이 선다.
- **월간 상품은 두지 않는다.** 연차 계획은 연초에 한 번 몰아서 한다. 월간이 있으면 1월에 한 달 내고 한 해 계획을 다 짠 뒤 해지한다.
- 구독 그룹 "Goldweek" 하나에 프로 연이 위 레벨, 플러스 연이 아래 레벨. 올리면 즉시 바뀌고 남은 기간은 애플이 정산한다.
  예전 패밀리도 같은 그룹에 남아 있다(구독자가 끝날 때까지).
- 구매력이 낮은 나라(인도네시아·베트남·태국·튀르키예·브라질·러시아)는 자동 환산보다 40~50% 낮게 직접 정한다.
- 올리기 · 졸업 · 평생 패스 상품은 App Store Connect 에 사람이 만든다. 없으면 그 버튼이 저절로 숨거나 비활성이다.

### 상품이 여는 칸 (`ProManager.tier(of:)` · `resolve`)

| 가진 것 | 칸 |
|---|---|
| 플러스 연 구독 · 플러스 평생 | 플러스 |
| 프로 연 구독 · 프로 평생 · 올리기 · 졸업 | 프로 |
| 패밀리 연 구독 (예전) | 프로 (구독이 끝날 때까지) |
| 받은 선물 | 프로 평생 |
| 언제나 평생 패스 (이 앱 또는 다른 앱에서 산 것) | 프로 (이 앱의 가장 높은 칸) |

같은 칸이면 평생이 구독보다 앞선다(설정의 '구독 관리' 줄은 구독일 때만 선다).
플러스 평생을 산 사람에게 페이월의 프로 평생 버튼은 올리기 상품을 판다.

### 구독 졸업 · 언제나 평생 패스

- **구독 졸업**: 구독 중인 사람에게 6개월째와 갱신 7일 전에 한 번씩 졸업가(프로 평생)를 보인다(`LeeoGraduation`).
  앱을 열고 다른 시트가 없을 때 뜬다(`ContentView`). 설정의 구독 관리 아래에 '평생으로 바꾸기' 줄이 늘 선다(구독 중일 때만).
  App Store 는 구독을 저절로 해지하지 않으므로, 산 뒤 해지를 안내만 한다.
- **언제나 평생 패스**: 세 칸 아래 한 줄(`LeeoForeverPassLine`). 패스 상품(`com.Ysoup.LeaveWise.forever` …)은
  `ProManager.allProductIDs` 에 넣지 않는다. 판정은 `LeeoForeverPass` 가 따로 하고(`ProExtras.pass`),
  열려 있으면 `checkEntitlement` 가 프로로 친다. 앱을 열 때와 복원할 때 `refresh()`.

### 수익 가정 (2.4.0, 검증 전)

설치 1만 건, 첫해 기준. 전환율·비율은 가정이고 배포 뒤 `purchase_plan`·`paywall_view` 로 고친다.
`purchase_plan` 슬라이스: plus · plus_lifetime · yearly(프로 연) · lifetime(프로 평생) · upgrade · graduate · family.

| | 2.99/7.99 단일 Pro | 트림 (2.4.0 가격) |
|---|---|---|
| 유료 전환율 | 3.0% | 2.2% (비싼 만큼 낮춰 잡음) |
| 상품 비율 | 연간 60 · 평생 40 | 플러스 15 · 프로 연간 45 · 프로 평생 15 · 패밀리 25 |
| 결제자 1명당 순매출 (수수료 15% 뒤) | 약 4.2 USD | 약 21.6 USD |
| 첫해 순매출 | 약 1,270 USD | 약 4,750 USD |

## 무료 한도 미리 알림 · 응원 · 선물

- **무료 한도**: 정책은 `GoldweekSpec.monetization` 의 `LeeoGatePolicy`(추천 등록 3개, 마지막 1칸 전부터 미리 알림)이고,
  판정은 `RecommendationGate`(LeeoKit `LeeoGate`) 하나다. 추천 화면 · 캘린더 탭이 같은 판정을 쓰고,
  무료 칸이 거의 끝난 카드 아래에 "무료로 넣을 수 있는 마지막 추천이에요" 같은 한 줄을 단다.
- **응원(팁)**: `com.Ysoup.LeaveWise.tip.small` · `.medium` · `.large` (소모성, 아무것도 열지 않는다).
  설정 "선물과 응원" 에 행이 서고, 홈에 부탁 카드(`LeeoTipAskCard`)가 선다.
  부탁은 **프로 트림 이상**에게만, 올해 추천으로 세운 계획 수(3 · 5 · 10)나 휴가 기록 수(30 · 100)를 넘어섰을 때만(`TipAskMoments`).
  얼마나 드물게는 LeeoKit 규칙(물으면 60일, 낸 사람은 180일, '다음에' 세 번이면 끝).
- **선물**: `com.Ysoup.LeaveWise.gift.pro` (소모성). 받은 사람에게 평생 프로(`com.Ysoup.LeaveWise.pro`)를 산 것과 같은 권한을 연다.
  기록은 `iCloud.com.Ysoup.FeedbackHub` 공개 DB(`LeeoGift` · `LeeoGiftRedemption`)와 받은 사람 비공개 DB(`LeeoGiftClaims`).
  이미 프로 이상을 **산** 사람은 받지 않는다(코드를 다른 사람에게 넘긴다).
- ⚠️ 팁 · 선물 상품은 `ProManager.allProductIDs`(= Spec 의 productIDs · entitlementIDs)에 넣지 않는다.
  넣으면 작은 결제가 Pro 를 연다. `MaturityFeatureTests.testGiftAndTipsNeverUnlockPro` 가 지킨다.
- 상품이 App Store Connect 에 없으면 그 행 · 카드는 저절로 숨는다(`isAvailable`).

## 기존 사용자

이미 산 사람, 구독 중인 사람, 그랜드파더, 선물 · 팁 받은 사람은 **권한을 그대로 유지**한다.
판매를 멈추는 상품도 권한 목록(`ProManager.allProductIDs`)에서는 빼지 않는다.

- 평생 구매자(4.99 USD에 산 사람 포함)는 **프로** 칸이다 (상품 ID 그대로). 2.4.2 부터 함께 쉬기 · 가족 기념일도 열린다.
- 패밀리 연 구독자는 구독이 끝날 때까지 프로와 같다. 기기에 남은 예전 칸 표시(패밀리, 3)는 프로로 읽는다.
- 2.4.0 전에 설치한 무료 사용자는 **2.4.0에서 새로 Pro가 된 기능을 계속 무료로 쓴다** (`ProFeature`, `ProManager.has(_:)`).
  - 판별 1: 2.4.0을 처음 켤 때 이미 온보딩을 마친 기기 (`proLegacyFreeFeatures`, 한 번 정하면 바뀌지 않는다)
  - 판별 2: 앱을 지웠다 다시 설치한 경우 `AppTransaction.originalAppVersion`(최초 다운로드 빌드 번호)이 11 이하
  - 설정의 "이용 중인 버전" 아래에 "계속 무료" 안내를 보여 준다
- 원래부터 Pro였던 기능은 이 혜택과 상관없이 `isPro`로 판단한다.

## 새 기능을 만들 때

1. 위 질문으로 무료인지 Pro인지 정한다.
2. 무료였던 기능을 Pro로 옮긴다면 `ProFeature`에 케이스를 넣고 `has(_:)`로 막는다. 기존 사용자를 보호하기 위해서다.
   처음부터 Pro인 새 기능은 `isPro`로 막는다.
3. 페이월 칸 카드(`PaywallView.features(of:)`)와 온보딩 Pro 목록(`ProShowcasePage.proFeatures`)을 실제 동작과 맞춘다.
